# Resource Ledger / 資源台帳

RimWorld 1.7向けに、物資の在庫・具体的な増減数・原因別内訳を確認するMODです。

[配布版](https://github.com/pengin0503/rimworld-ResourceLedger/releases) · [CI](https://github.com/pengin0503/rimworld-ResourceLedger/actions/workflows/verify.yml)

0.3.1では、原因別記録で繰り返される範囲別の集計を減らしました。操作前後のマップ走査は引き続き行います。

0.3.0では、全種類の自動追跡で問題になる記録・保存・画面の負荷を改善し、全拠点を対象にした通知に対応しました（Issue #8〜#12）。0.2.2までの修正を含め、詳細は [REVIEW.md](REVIEW.md) を参照してください。

## ゲーム内でできること

- 所有している全種類のアイテムを自動追跡します。資材・食料・薬・武器・衣服・装備中の品・梱包済み家具に対応します。MOD追加物資も入手時に追加します。
- 「現在庫あり」「期間中に変動あり」「履歴あり・全種類」を切り替え、名前・識別名・カテゴリ・追加元MOD・お気に入りで絞り込めます。絞り込んでも記録は続きます。
- 詳細画面の大きな数値欄で、現在庫・期間増加・期間減少・純増減・推定残日数を確認できます。増加は緑、減少は赤、在庫は青で表示し、符号も付けます。
- **在庫は棒グラフ、増加・減少・純増減は折れ線**で同時表示します。左軸が在庫、右軸が増減です。両軸はそれぞれ1・2・5の系列で読みやすい目盛りに調整します。
- 増加は実線、減少はゼロ以下の破線、純増減は点線です。各線の表示を切り替えられ、凡例から物資を隠せます。最大6種類を比較できます。
- 集計間隔は自動・1時間・1日から選択できます。大量の点や集約済みの古い履歴では、実際に利用できる粒度に調整します。グラフ上の集計表示とツールチップに実際の期間を示します。
- カーソル位置で、同じ記録区間の期末在庫・増加・減少・純増減を実数で確認できます。端数区間はその区間の合計として明示します。
- 記録がある範囲を拡大表示し、導入前の長い空白を抑えます。記録欠落をまたいで線を結びません。
- 原因別集計、行動明細、保管場所の表示、担当者・設備・保管場所へのジャンプ、通知、CSV出力を利用できます。
- マップ全体、保管場所のみ、指定した保管場所、全拠点合計を切り替えられます。単位は個数・栄養量・基準市場価値です。
- 下部メニューに専用の台帳アイコンを追加します。アイコンにカーソルを合わせると説明を確認できます。キー設定で開閉キーも割り当てられます。

## インストール方法

必要環境は **RimWorld 1.7（Waylith）とHarmonyの1.7対応版**です。

1. Releasesから最新の `ResourceLedger_<版>_Mod.zip` をダウンロードします。
2. ZIPを展開し、中の `ResourceLedger` フォルダーを `RimWorld/Mods` に配置します。
3. `Mods/ResourceLedger/About/About.xml` となっていることを確認します。
4. ゲーム内のMOD一覧で有効にし、Harmony・Coreより後に読み込ませて再起動します。
5. セーブを読み込み、画面下部の資源台帳アイコンを開きます。

`Source.zip` は開発用です。`bundle.zip` にはゲーム用ZIPとソースZIPが含まれます。
0.1.0・0.2.0・0.2.1から更新する場合は同じ `ResourceLedger` フォルダーを置き換えてください。パッケージIDは変わっていません。

## 追跡範囲と履歴

対象はプレイヤーの本拠地にある可視の地面・棚・対応コンテナと、所属ポーンの所持・運搬・装備品です。敵・訪問者・商人の携帯品、霧で未発見の品、死体、建築中の枠へ消費済みの材料は含めません。未完成品は材料を数えます。設置済みの建物は在庫に含めず、梱包済みのものは実際の家具名で数えます。

種類はThingDef単位です。品質・材質・耐久度による細分化は行いません。在庫がゼロになっても、その種類の履歴は残ります。

途中セーブから追加できる設計で、記録は導入後から始まります。初めて観測した既存の物資は開始残高にします。0.1.0の履歴を読み込み、追加対象となった武器・衣服などは更新後の初観測から記録します。

現在庫は最後の在庫確認時点、グラフ・期間収支は定期記録時点の値です。「更新」でその時点の記録を追加できます。未記録の過去を0で埋めません。記録不足や欠落区間では集計値を「—」で示します。

## 原因別内訳・通知・CSV

採掘、収穫、生産、レシピ材料、建築、解体回収、食事、薬物、治療、燃料、畜産、売買、贈与、クエスト報酬、移出入、腐敗・損失などを、対応するゲーム処理から記録します。同じ範囲内での運搬・スタックの分割や結合は収支に重ねて数えません。

在庫差と取得できた原因別収支を照合し、残りは「原因不明」の調整として明示します。差分が0でも、対応していない生産と消費が相殺した可能性は残ります。すべてのMOD固有処理の原因取得を保証するものではありません。

通知には下限・上限・減少量・減少率・推定残日数を設定できます。「現在の全拠点」を選んで作った通知は、すべての本拠地の合計で判定します。存在しなくなったマップの通知は自動で削除します。再通知の間隔、解除幅、ミュートも調整できます。予測は直近の連続した記録を使い、売買・移出入の影響も含みます。

CSVはサマリー・履歴・原因別・行動明細を出力します。保存先はRimWorldのセーブデータフォルダー内 `ResourceLedgerExports` です。日本語向けUTF-8 BOMと表計算ソフトの数式対策を含みます。

## 保存・負荷

記録間隔は1～24時間、詳細保持日数・件数、時間別／日別履歴の保持期間を設定できます。古い時間別履歴は日別へ集約します。集約は前回から新しく古くなった区間だけを処理するため、履歴が長くなっても処理時間は増えません。在庫が変わらない間は1つの区間を延長して記録し、グラフや期間集計ではその区間の各時点の値として扱います。保存データはgzip圧縮し、0.1.0の非圧縮形式も読み込めます。記録設定画面に、現在の記録量と前回のセーブ／読み込み時の台帳サイズを表示します。

目安（ゲームを使わないコアだけの計測、環境により変動）：300種類×2範囲・100日、毎時記録の場合、1回の集約は最大約2〜9ms（0.2.2では約240ms）。保存データは全種類の在庫が一定なら約0.01MB、1割の種類が毎時変動する場合で約2.4MB（0.2.2では在庫一定でも約15MB）。

実際に発見した種類を登録し、一覧は画面内の行だけ描画します。グラフの描画点数も制限します。画面を開いたまま進めても、一覧の再計算は定期記録時と、現在庫の更新を実時間1秒に1回までに抑えます。原因記録では処理の前後に在庫を確認します。植物・汚れ・ふつうの建物など物資を持てない物は走査しません。それでも処理ごとにマップ上の物資を走査するため、大規模コロニーでの実TPSへの影響はゲーム内での確認が必要です。負荷が気になる場合は「運搬・マップ間移動も記録する」を無効にしてください。「診断」で処理時間や取得状況を確認できます。

## 検証状況

自動テスト、実際の1.7 DLLを使うビルド・API互換性検証、Harmonyの適用／解除、翻訳・XML・配布ZIPの検査を実行しています。詳しくは [VALIDATION.md](VALIDATION.md) を参照してください。

**0.3.1の画面表示・通常プレイ・セーブ更新を実際にゲームで確認する作業は未実施**です。そのためプレリリースとして配布します。

## 開発・CI

.NET SDK 10を使用します。Windowsでは次のコマンドでビルド・検証・ZIP作成を実行できます。

```powershell
./build.ps1 -GameDir 'D:/SteamLibrary/steamapps/common/RimWorld' -HarmonyPath 'D:/path/to/1.7/Assemblies/0Harmony.dll' -RunTests
```

`GameDir` は `Assembly-CSharp.dll`、`UnityStubs.dll`、`Waylith.dll` があるフォルダーです。

GitHub CIはゲーム非依存のコアをビルドしてテストし、翻訳・XML・アイコンと、ビルド済みMOD DLLのソース指紋・ハッシュを検証して配布ZIPを作ります。UIを含む全体ビルドは各自のゲームDLLを参照して行ってください。ゲーム本体DLL・Harmony DLLはリポジトリや配布ZIPに含めません。

mainへの反映で新しいバージョンが検証を通ると、プレリリースを作成します。既存の同じバージョンのリリースは保持します。

## English

Resource Ledger tracks all discovered owned item types, including equipment and minified furniture. Stock bars and signed flow lines share a timeline with independent readable axes. It includes exact quantities, cause breakdowns, filtering, comparisons, alerts, locations and CSV exports. Requires RimWorld 1.7 and Harmony for 1.7. Install the Mod ZIP in `RimWorld/Mods`. Recording starts after installation; existing 0.1.0 history is preserved. This is an experimental release: actual in-game UI/gameplay validation remains pending.
