# Resource Ledger / 資源台帳 0.1.0
RimWorld 1.7向けの資源管理MODです。**ゲーム画面と通常プレイでの実機確認前の試験版**です。

## ゲーム内でできること
- 現在庫、期間の開始数・終了数、増加数、減少数、純増減、増減率、1日平均を一覧で確認。
- 在庫の折れ線、日別の増加・減少、カーソル位置の正確な数値を表示。比較は最大6資源、凡例をクリックして表示を切り替え。
- 個数・栄養量・定義上の市場価値の換算表示。価値は過去の実売価格や当時の資産額ではありません。
- 採掘、深部採掘、伐採・収穫、製造・調理、建築投入、解体回収、食事・薬物、治療・手術、燃料補充、畜産、売買・贈与、クエスト物資、移出入などの原因別内訳。
- 現在の拠点／全拠点、マップ全体／保管場所内／選択した保管場所で集計。
- MOD追加資源の選択、検索、追加元MOD・分類での絞り込み、お気に入り、並べ替え、表示列の保存。
- 在庫上下限、期間の減少数・減少率、推定残日数による通知。解除余裕幅、再通知間隔、ミュートを設定。
- 所在、担当者・設備の明細。現在も対象が存在すればクリックで移動。
- 選択した表示単位・期間・範囲でCSV出力。日本語はUTF-8 BOMで保存。
- 記録間隔、履歴の保存期間、明細件数を調整。診断画面に実際の記録処理時間を表示。

生産数や消費数をゲーム上で変えるMODではありません。自動生産指示や自動売買も行いません。

## インストール
1. 同梱の `ResourceLedger_0.1.0_Mod.zip` を展開します。
2. 中の `ResourceLedger` フォルダーをRimWorldの `Mods` フォルダーへコピーします。
3. `Mods/ResourceLedger/About/About.xml` という配置になっていることを確認します。
4. **1.7対応版のHarmony**を有効にし、その後に `Resource Ledger / 資源台帳` を有効にしてゲームを再起動します。
5. 拠点を開き、画面下部の「資源台帳」を選びます。

Harmonyやゲーム本体DLLは同梱していません。他のMore Graphs等を必須にしない独立MODです。
途中セーブに追加する設計ですが、実際の途中導入・削除後ロードの実機試験は未実施です。
試験版を使う際は、既存セーブのコピーで確認してください。
既に同じpackageIdの版を使っている場合は、古い版と二重に有効にしないでください。

## 最初の使い方
- 「追跡資源」で見たい資源を選びます。MOD追加資源も候補に出ます。
- 初回の数量は開始在庫として扱い、入手数へは加算しません。導入前の履歴は作れません。
- 既定はゲーム内1時間ごとの記録です。最初の期間収支には2つの記録点が必要です。
- 資源名をクリックすると詳細画面になります。比較したいものは一覧左のチェックを入れます。
- 「保管場所の集計範囲を作成」では、名前を入力して倉庫・棚を選びます。
- 通知設定は資源詳細の「資源の通知」から作成します。数量しきい値は個数単位です。
- ショートカットは初期状態では未割当です。ゲームのキー設定で「資源台帳を開く」を割り当てられます。
- CSVの保存先は出力後の画面に表示されます。ゲームのユーザーデータ領域内の `ResourceLedgerExports` です。

## 数字の読み方
「生産100・材料消費60」で在庫が40増えた場合、増加100／減少60／純増40と表示します。
同じ資源の生産と消費が相殺される場合も、対応した製造完了処理では両方を残します。
「原因未分類」は、在庫の実測と確認済み収支の差分です。**差分0でも、全原因の捕捉を保証しません。**
未対応MODが同じ時間帯に100個作り100個使うと、在庫の比較だけではその内訳は分かりません。
運搬・スタック結合は生産と区別します。建築材料は建築フレームへ投入した時点で在庫から外します。
未完成品に保持された材料は、完成または消費されるまで在庫に含めます。
保管場所の搬出は、拠点全体の消費とは別です。

在庫と履歴の確定時刻には違いがあります。表とグラフの期間収支は共通の記録点に揃え、
比較に使った実際の開始・終了時刻を詳細画面に表示します。
未記録やマップ構成変更の区間は0として補いません。不連続期間の増減は算出保留です。
全拠点表示は、現在の各拠点で共通して記録されている期間に揃えます。
全拠点一覧からの行動明細CSVは各資源・拠点の選択期間の記録、詳細画面からの出力は表示中の確定期間が対象です。

枯渇予測は直近5日を対象とし、最低1日分の連続した実測から計算します。
季節や将来の作付けは予測せず、売買・移出入も含めた最近の純減ペースです。
定義が削除された資源は履歴の名前を保持します。栄養量・価値の換算には最後に記録できた定義値を使います。

## 記録対象と互換性
- プレイヤーのホーム拠点を対象とします。キャラバンの内部や一時的な遭遇マップは集計対象外です。
- 可視の地面・棚・対応コンテナー、所属ポーン・動物・メカの携帯／運搬品を数えます。
- 商人や敵の携帯品、未採掘鉱石、未収穫作物、建築に投入済みの材料は除外します。
- 通常のThingHolder APIで内容を公開しない特殊収納や、独自処理の自動工場は未検証です。
- 読み取りに失敗した収納は数量0にせず、該当拠点の記録を保留して画面に表示します。
- MOD独自の材料消費・物流・追加収穫、独自シャトルやグラヴシップの個別原因まで完全には識別しません。
- グラヴシップ等でマップの構成が変わった場合は、不連続区間として扱うことがあります。
- 原因記録では、対象の操作の前後に在庫を確認します。多くの運搬・大量の資源・複数拠点では負荷が増えます。
- 処理負荷が気になる場合は、追跡資源を絞るか「運搬・マップ間移動」「原因別の収支」を調整できます。

既定の保存量は、時間単位60日・日次600日・行動明細7日または20,000件です。
明細を削除しても、保存期間内の集計値は別に保持します。期間を短くした後の古い履歴は復元できません。
設定値と対象資源数により、セーブ内に保存するデータ量は増えます。

## 検証状況
実本体 `1.7.4985 rev1269` を参照してReleaseビルドし、集計・保存・通知・CSV・実API契約を自動検証しています。
Harmonyのパッチ適用・解除も、実DLLを読み込んだ独立テストプロセスで確認しています。
**ゲーム画面の描画、実際の通常プレイ、大規模MOD構成での負荷、セーブへの追加・削除は実機未検証です。**
詳しくは `VALIDATION.md` を参照してください。1.6用のバイナリは含みません。

## ソースからのビルド
.NET 10 SDK、Python 3、手元の1.7本体、Harmonyの1.7 DLLが必要です。
ソースZIPを展開し、PowerShellで次のように実行します（パスは自分の環境に合わせて指定）。

```powershell
./build.ps1 -GameDir "X:/SteamLibrary/steamapps/common/RimWorld" -HarmonyPath "X:/SteamLibrary/steamapps/workshop/content/294100/2009463077/1.7/Assemblies/0Harmony.dll" -RunTests
```

ゲームDLLを使わない基礎テストだけなら `dotnet run --project tests/ResourceLedger.Tests.csproj -c Release` で実行できます。
依存ライブラリをネットからダウンロードする構成ではありません。必要な.NET 10参照パックはSDK側に必要です。
このソースをビルドしても、ゲームのインストール先へは自動配置しません。

## English
Resource Ledger provides exact inventory deltas, verified cause breakdowns, graphs, comparisons, configurable alerts, locations and CSV exports.
Requires RimWorld 1.7 and its matching Harmony build. This is an experimental release: build, logic and patch contracts were tested, but live gameplay and graphical UI were not.
Unrecognized changes are explicitly reconciled as unclassified; a zero reconciliation difference is not proof of complete event capture.
