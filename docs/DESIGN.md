# 資源台帳（Resource Ledger）設計仕様書
日付: 2026-10-22
状態: ユーザー承認済み（2026-10-22）。実装の検証状況はVALIDATION.mdを参照。
対象: RimWorld 1.7を優先。1.6対応は本版の必須要件に含めない。
作業方法: サブエージェントを使わず、同一セッションで実装・検証する。

## 1. 目的と合意済みの範囲
資源が「今いくつあるか」「指定期間で何個増減したか」「何によって増減したか」を、
グラフと数値で把握し、不足・余剰への対応につなげる独立MODを作る。
グラフ、具体的な増減数、原因別内訳、関連する便利機能を含む構成は会話で承認された。
途中セーブから導入し、導入後の履歴を記録する。導入以前の履歴は復元しない。
日本語と英語の表示に対応する。ゲームの資源生産量や消費量、作業指示は変更しない。

本書で初めて定める既定値・集計境界・保存方式は設計上の提案であり、既に承認された事実とは区別する。
公開・Steam Workshopへのアップロード・GitHubへの送信は別途指示があった場合に行う。
成果物はゲーム導入用ZIP、ソースコード、ゲーム内での説明とインストール方法を含むREADMEとする。
READMEには検証済み環境と未検証事項も記載する。導入用ZIPには開発用ファイルを入れない。

## 2. 方式の比較と選択
| 方式 | 利点 | 制限 |
|---|---|---|
| 定期的な在庫数の比較のみ | 構成が簡単でMOD追加資源を数えやすい | 生産・消費の内訳を復元できない |
| 全量を行動イベントだけで記録 | 原因の詳細を記録できる | 未対応処理の取りこぼしが累積しやすい |
| 在庫の定期確認＋原因別イベント | 在庫差との整合を確認しつつ原因を示せる | 集計と重複防止の設計が必要 |

3番目を採用する。実在庫を在庫表示の基準とし、原因イベントが在庫値を直接上書きしない。
原因を推測で確定せず、確認できない差分は「原因未分類の調整差」として表示する。
調整差が0でも、すべての入出庫原因を捕捉できたことは保証しない。
例えば未対応の生産100個と消費100個が同じ期間に起きた場合、在庫差は0となり内訳を復元できない。

## 3. 在庫の境界と対象
### 3.1 基本の対象
追跡はアイテム定義の識別子と個数を単位とし、表示名でデータを結び付けない。
既定の一覧は木材・主要金属・シルバー・コンポーネント・主な食料・医薬品から構成する。
MOD追加アイテムは検索候補に自動追加し、ユーザーが追跡対象へ登録できる。
新たに追跡を始めた資源には開始時刻を記録し、過去の未記録期間を0と扱わない。
栄養量・市場価値は個数から独立した表示単位とし、異なる単位を同じ縦軸に混在させない。
材質別の耐久装備分析などは本版の必須範囲に含めず、スタック可能な資源・食料・製品を優先する。

### 3.2 既定のマップ在庫
対象拠点の可視の地面・棚・対応する収納内の対象アイテムと、
その拠点にいるプレイヤー所属ポーン・動物・メカの携帯／運搬中アイテムを数える。
訪問者・商人・敵の携帯品、未採掘鉱石、未収穫作物、建物に組み込まれた材料は含めない。
運搬中アイテムを地面と携帯品の両方で数えず、同じ個体を重複集計しない。
禁止フラグだけでは既定の集計から除外しない。霧の中の未発見品は含めない。
対応できない特殊収納は集計対象外であることを明示し、数量を推定して追加しない。

### 3.3 集計範囲の切替
「マップ在庫」「保管場所内のみ」「指定した保管場所」を切り替える。
各範囲の履歴と開始時刻を別に扱い、変更前後の数量差を消費として記録しない。
保管場所への出入りは「集計範囲への搬入／搬出」とし、生産・消費とは区別する。
範囲外で発生した出来事は、その範囲の実在庫に影響しない限り収支へ含めない。
拠点別の比較と全拠点の合計表示を用意する。
キャラバン、輸送ポッド、グラヴシップ等で境界を越える資源は移出／移入として扱う。
移動を識別できない処理は原因未分類とし、生産・消費へ自動分類しない。
マップの生成・削除・離着陸などで集計対象の構成が変わる区間には構成変更を表示する。
履歴が存在しないマップや読み取れない区間を0で埋めず、合計値の比較不能区間を表示する。

## 4. 原因別収支と照合
### 4.1 分類
| 増加 | 減少 |
|---|---|
| 採掘・深部採掘 | 建築・修理への投入 |
| 伐採・収穫 | 製造・調理の材料消費 |
| 製造・調理・精錬 | 食事・薬物摂取 |
| 解体・回収 | 治療・手術 |
| 解体調理・搾乳・毛刈り・採卵 | 燃料補充 |
| 購入 | 売却 |
| 贈与・クエスト報酬 | 贈与・クエストへの納品 |
| 拠点への移入・範囲への搬入 | 移出・範囲からの搬出 |
| 原因未分類の増加調整 | 腐敗・焼失・破壊、原因未分類の減少調整 |

分類は対応を確認できたゲーム処理にだけ適用する。MOD独自処理への完全対応は保証しない。
出来事の時刻、資源、数量、原因、拠点を保存する。担当者・設備は取得できた場合のみ付加する。
医薬品などが消費された事実を記録し、処理開始の予約数だけで消費を確定しない。
解体調理は消費アイテムと生成物をそれぞれ記録し、物量が保存すると仮定しない。

### 4.2 重複防止
上位の作業と下位の個数変更を同じ収支として重複記録しない。
作業の文脈と確定した実数量の変化を結び付け、失敗・キャンセル・部分完了を区別する。
スタックの分割・結合、棚への収納、手に持つ／置く操作は、同じ集計範囲内では収支0とする。
製造品の出現と材料の消失は別資源の収支として記録し、同じ資源を入出力するレシピも扱う。
作業完了前の中間状態を保存した場合も、ロード後に確定収支を二重計上しない。

### 4.3 照合ルール
同じ資源・拠点・範囲・時間境界について、次を満たす。
期末在庫 − 期首在庫 = 確認済み増加 − 確認済み減少 ＋ 符号付き原因未分類調整差。
原因未分類は増加・減少を別に保持し、「内訳不明」と表示する。
基本履歴の確定時刻とイベントの締め時刻を一致させ、中間処理中に照合しない。
明細に記録不足・未対応・対象外収納の状態を表示する。
記録開始前、対象変更直後、未ロード等で不連続な期間は、完全な期間比較として表示しない。

## 5. 画面
### 5.1 一覧
専用の「資源台帳」タブと変更可能なショートカットで開く。
列は現在庫、期間の開始数／終了数、増加、減少、純増減、増減率、1日平均、予測、状態。
列の表示切替、並べ替え、文字検索、分類・追加元MODによる絞り込み、お気に入り固定に対応する。
増減率は期首が0なら数値を捏造せず「算出不可」とする。
現在庫の取得時刻と履歴の最終確定時刻を区別し、比較は確定済みの共通境界に揃える。
期間は直近1・5・15・60日、任意の開始終了日。ゲーム内日数を使う。

### 5.2 資源詳細
上部に現在庫・期間収支・推定枯渇日数、中央に在庫折れ線／日別収支棒グラフを表示する。
カーソル位置の日付・正確な数量を表示し、期間拡大、凡例による線の表示切替に対応する。
複数資源比較では個数の実数軸と相対変化の表示を切り替え、モードを明示する。
下部に原因別集計と時系列の明細を表示し、担当者・設備を確認できる場合は表示する。
記録欠落や未記録区間を線で結んで連続データのように見せない。

### 5.3 所在
地面・棚・保管場所・携帯者ごとの現在量を一覧にする。
対象が現在も存在する場合、クリックで移動・選択する。
明細の過去の担当者・設備が消失していたら、履歴文字列を残し移動ボタンを無効にする。

## 6. 不足予測・通知
既定は直近5日間の在庫の純変化率から推定し、1日・15日の平均も選べる。
負の平均なら現在庫／1日あたりの純減を枯渇までの日数とする。
非減少時は「減少傾向なし」、記録不足・不連続時は「判定保留」とする。
最低1日分の連続記録を必要とし、選択期間に満たない場合は使用した実日数を表示する。
季節・将来の作付け・未完了の作業を予測に織り込まない。売買や移出の影響も含む推定であることを示す。
在庫下限・上限、指定期間の減少量／減少率、予測残日数に通知条件を設定できる。
条件ごとの有効化、解除条件の余裕幅、再通知間隔、ミュートを設定し、毎tick通知しない。
設定画面で作った条件と、通知の判断に使った実数を確認できる。

## 7. 記録・保存・性能
ゲーム内1時間ごとの在庫履歴を既定とし、記録間隔は設定可能とする。
原因イベントは対応処理の確定時に取得し、資源・原因・時間帯ごとの集計へ加算する。
詳細グラフ用の時間単位履歴は60日、日次集計は600日を既定保存期間とする。
詳細な行動明細は直近7日または20,000件の先に達した上限まで保持する。
上限到達時は古い行動明細だけを破棄し、時間別・日別の集計値は保持する。
明細を削除した期間にも「明細保存期限外」と表示する。
対象資源数・保存期間・明細件数の設定に応じ、保存対象の規模を設定画面で確認できる。
毎フレームのマップ全走査を避ける。画面の計算結果は再利用し、描画から集計を独立させる。
分割走査を使う場合、走査中のイベントとの時刻整合が確認できる方式に限定する。
在庫確認の処理時間、履歴点数、行動明細件数を診断表示し、負荷を実測できるようにする。
性能が未測定の段階で「負荷ほぼゼロ」と案内しない。

## 8. データ構造と責務
InventoryReader: 資源と集計範囲を受け取り、重複のない現在庫と取得状態を返す。
EventCapture: 検証済みの処理から原因・実数量・時刻・所在境界を捕捉する。
Ledger: 原因イベントの重複防止、同じ境界での照合、時間／日次集約を担当する。
HistoryStore: スキーマ版、記録開始時刻、資源識別子、拠点識別子、集計、明細、設定を保存する。
QueryService: 期間比較、原因別集計、予測、複数資源比較の結果を提供する。
AlertService: 確定済みのデータから通知条件を評価し、再通知を制御する。
UI: 一覧・グラフ・内訳・所在・設定を描画する。生のゲーム処理を変更しない。
Export: 同じQueryServiceの結果をCSVへ書き出す。
ゲームバージョン依存部分はInventoryReaderとEventCaptureに集め、集計計算を分離して検証可能にする。

## 9. CSV・設定・互換性
CSVは履歴・日別収支・原因別集計・保存中の行動明細を出力する。
UTF-8 BOM、桁区切りのない数量、ゲーム内時刻、拠点名、資源名と識別子、単位を含める。
画面と同じ期間・範囲で出力し、未記録と0を区別する。ファイル名を衝突させない。
出力先はゲームの利用可能なユーザーデータ領域を実装時に確認して選ぶ。
設定は表示設定とセーブ固有の追跡・通知設定を分離する。
MODの追加・削除でアイテム定義が消えても、履歴の識別子・保存名を保持して読めるようにする。
未知の将来版データを黙って上書きしない。読み取れない部分は状態を表示して隔離する。
途中導入時には初期在庫を基準値として記録し、入手イベントに加算しない。
途中削除で資源やポーンへ影響を与えない設計とし、削除後ロードも検証対象とする。
独自収納、物流MOD、自動工場MODとの対応は試験で確認できたものだけを列挙する。

## 10. 検証と合格条件
1. 初期100個、生産100個、消費60個で、期末140個、増加100、減少60、純増40になる。
2. 同じ時間帯の入出庫を、在庫の純増減だけへ潰さず記録できる。
3. 同じ範囲内の運搬・スタック分割結合・収納移動で、生産／消費が増えない。
4. 複数段階の作業と下位メソッドの捕捉が同じ消費を二重計上しない。
5. 作業失敗・キャンセル・部分完了・処理途中のセーブロードを実数量で扱う。
6. 売買・贈与・拠点移動を生産／消費と区別する。
7. 未対応処理の純差は原因未分類へ入り、在庫と収支が一致する。
8. 未対応の増加減少が相殺された場合に、内訳の完全捕捉を主張しない。
9. 新規追跡、集計範囲変更、マップ構成変更、未ロードを資源枯渇として誤通知しない。
10. 0在庫、0期首、非減少、記録不足で増減率・予測が正しく表示される。
11. 日次集約・明細上限・セーブロード後にも合計が維持される。
12. MOD追加資源、消失した定義、消失した担当者／設備で画面が開ける。
13. CSVの期間・資源・範囲・数値が画面と一致する。
14. 日本語を含む検索・名称・CSVと、長い資源名のレイアウトを確認する。
15. バニラ相当の最小構成で新規開始／途中導入／削除後ロードを実機確認する。
16. 原因別に代表操作を実行し、実在庫・明細・日次集計を突き合わせる。
17. 記録の有無、対象資源数、明細保存の有無で処理時間とセーブ量を測定する。

集計・照合・保存移行・通知の境界は自動テストを行う。
ゲーム依存の捕捉とUIは実際の1.7 APIとゲーム内の検証が必要で、コンパイル成功だけで合格としない。
本体DLLの版、Harmony等の必要依存、ビルド方法は実装計画の前に確認する。
本セッションではまだゲーム本体のAPIや実機挙動を検証していない。
実機確認ができない場合は、未確認項目を明示して試験版として渡す。

## 11. 自己レビュー
在庫と収支の式、原因不明の相殺、運搬境界、期間の欠落、保存上限の関係を本文で定義した。
既存MODとの完全互換や1.7での動作実績を未確認のまま保証していない。
便利機能は資源の観測・分析・通知・所在確認・出力に限定した。
自動生産指示、経済シミュレーション、電力設備管理などの別機能は本版の範囲外とする。
実装着手前に本書をユーザーが確認し、その後に実装計画を作る。
