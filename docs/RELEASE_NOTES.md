原因別記録で操作ごとに繰り返す処理をさらに軽量化しました。0.3.1の変更（範囲別集計の削減）も含みます。

- 初期記録の確認は、追跡中の種類が増えたときと新しい範囲だけで行います。これまでは1操作につき範囲ごとに3回、追跡中の全種類分の記録名を作って確認していました。
- 新しい種類の発見と原因記録の受付は、追跡一覧から毎回作っていた検索用の集合を再利用します。
- 在庫の走査では、保管場所の識別名を場所ごとに1回だけ作ります。所在名は所在一覧に表示するときに作り、物資の種類の判定は種類ごとに保存します。

500種類・3範囲の合成データでは、マップ走査を除く記録処理が1操作あたり約0.72 ms→約0.06〜0.08 ms、メモリ確保が約990 KiB→約16 KiBになりました。操作前後のマップ走査は引き続き行います。走査の改善幅と、実ゲームのTPSへの効果は未測定です。
